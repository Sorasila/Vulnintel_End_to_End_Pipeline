## S4a (Databricks)

### คำถาม

GitHub Actions ยืนยันตัวตนกับ Databricks Free Edition workspace ด้วย service principal OAuth (M2M) ได้ไหม ถ้าไม่ได้ PAT มีข้อจำกัดอะไร

เกณฑ์:

- **ผ่าน:** ทั้ง 4 check (`current_user.me`, `files.upload`, `sql.select_1`, `jobs.list`) สำเร็จด้วย OAuth M2M → ใช้ service principal และตั้ง `run_as` ของ bundle เป็น SP
- **ไม่ผ่าน:** ใช้ PAT, เพิ่มงาน "ต่ออายุ PAT" ใน runbook และให้ workflow keepalive เตือนก่อน PAT หมดอายุ 14 วัน

### setup

- Workspace: Databricks Free Edition, host `dbc-9895c944-aa73.cloud.databricks.com` (ดู `_environment.md`), serverless เท่านั้น
- โค้ด: `spikes/s4/dbx_auth_check.py`, workflow `.github/workflows/spike-s4a.yml` (`workflow_dispatch`, input `auth_type` = `oauth` | `pat`)
- SQL setup: `spikes/s2/setup.sql` (catalog `vulnintel_dev`, volume `landing`)
- GitHub Secrets: `DATABRICKS_HOST` (`https://dbc-9895c944-aa73.cloud.databricks.com`), `DATABRICKS_CLIENT_ID`, `DATABRICKS_CLIENT_SECRET`; สำหรับ PAT: `DATABRICKS_TOKEN`
- GitHub Variable (ไม่บังคับ): `DATABRICKS_WAREHOUSE_ID` (ถ้าไม่ตั้ง script ใช้ warehouse แรกจาก `warehouses.list()`)

### ขั้นตอนที่ทำจริง

ขั้นตอนที่ [คุณ] ทำเอง เรียงตามลำดับ:

1. รัน `spikes/s2/setup.sql` ใน SQL editor (ส่วนที่ไม่ใช่ grant) ถ้าชื่อ volume `_checkpoints` ถูกปฏิเสธ ให้ใช้ `checkpoints` และบันทึกใน `docs/spikes/S2.md`
2. สร้าง service principal และ OAuth secret: Workspace settings → Identity and access → Service principals → Add → สร้าง OAuth secret (เก็บ secret ไว้ใส่ GitHub Secrets ทันที เพราะดูซ้ำไม่ได้) ถ้าเมนูหรือปุ่ม secret ไม่มี ให้ capture หน้าจอแล้วข้ามไปขั้น 6
3. ให้สิทธิ์ SP: เอา comment ของ GRANT ใน `setup.sql` ออก แทน `<sp-application-id>` ด้วย Application ID ของ SP แล้วรัน และให้ CAN USE บน SQL warehouse (เมนู SQL Warehouses → Permissions)
4. เพิ่ม GitHub Secrets `DATABRICKS_HOST` (ค่า `https://dbc-9895c944-aa73.cloud.databricks.com`), `DATABRICKS_CLIENT_ID`, `DATABRICKS_CLIENT_SECRET`
5. รัน workflow `spike-s4a` ด้วย `auth_type=oauth` แล้วบันทึกผลทั้ง 4 บรรทัดลงหัวข้อหลักฐาน
6. ถ้า OAuth ไม่ผ่าน: สร้าง PAT เก็บเป็น secret `DATABRICKS_TOKEN` แล้วรัน workflow ซ้ำด้วย `auth_type=pat` บันทึก lifetime สูงสุดที่ตั้งได้และวันหมดอายุ
